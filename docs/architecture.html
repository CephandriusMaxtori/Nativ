Design decisions

Zero Cgo

All Windows API and OpenGL calls use syscall and golang.org/x/sys/windows to dynamically load DLLs and call functions at runtime. No C compiler, no GPU SDK, no external DLLs to ship.

  • Single-binary deployment
  • Trivial cross-compilation
  • No C toolchain in CI
  • Easy go build / go test

Platform abstraction

The Platform interface abstracts OS-specific windowing:

  • CreateWindow, Pump, Destroy, PostQuit
  • Build tags select the right implementation
  • Non-Windows builds compile but return ErrUnsupported at runtime

Renderer backends

The Renderer interface abstracts GPU rendering:

  • Init (with window width/height), Draw, Shutdown, SetSize
  • Backends self-register via init() functions
  • RegisterBackend / NewBackend / ListBackends

Text rendering

Glyphs are rasterized into alpha-mask atlases and uploaded to the GPU once, then drawn through the same textured-quad pipeline as solid rectangles:

  • The built-in 7x13 bitmap font needs no setup
  • Custom TTF/OTF fonts are parsed with sfnt and rasterized with opentype at any size
  • Each unique font+size pair gets its own cached atlas
  • The fragment shader samples the atlas .r channel as alpha so glyphs composite over any color

Widget tree

Widgets form a tree with parent/child relationships:

  • Widget interface: Bounds, SetBounds, Draw, HandleEvent
  • BaseWidget provides default implementations
  • BoxLayout distributes space evenly among children
  • Events dispatch in reverse Z-order (last child wins)

Message pump

The Win32 message pump uses PeekMessageW (non-blocking) to drain the message queue each frame, then falls back to WaitMessage when idle. This allows continuous rendering for animations while keeping CPU usage near zero when the window is idle.
